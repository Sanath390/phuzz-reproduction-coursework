Follow these steps in order.

1.Install WSL 2 and Ubuntu.

  Open PowerShell as Administrator and run:
    wsl --install -d Ubuntu-24.04

  Open Ubuntu 24.04 from the Start menu. Create the Linux username and password it requests. When entering the password, the terminal will not display characters.

  Back in PowerShell, run:
    wsl --update
    wsl -l -v
  
  Check that Ubuntu-24.04 shows VERSION 2. If it shows 1, run:
    wsl --set-version Ubuntu-24.04 2

  Install basic tools inside Ubuntu.
    Open the Ubuntu terminal and run:
      sudo apt update
      sudo apt install -y git curl jq less

2.Install Docker Desktop on Windows and connect it to Ubuntu.

  Download Docker Desktop from the official website: https://www.docker.com/products/docker-desktop

  Install Docker Desktop and follow the installation instructions.

  After installation, open Docker Desktop and go to Settings > Resources > WSL Integration. Enable integration with Ubuntu-24.04.

  Back in the Ubuntu terminal, run:
    docker version
    docker compose version
    docker run --rm hello-world
  Check that:
  - docker version displays both Client and Server information.
  - docker compose version prints a version.
  - The final command prints Hello from Docker!

3.Install VS Code on Windows and its WSL extension.

  Download Visual Studio Code from the official website: https://code.visualstudio.com/

  Install VS Code and follow the installation instructions.

  Open VS Code and go to Extensions (Ctrl+Shift+X). Search for "Remote - WSL" and install it.

  After installation, click on the green button in the bottom-left corner of VS Code and select "New WSL Window". Choose Ubuntu-24.04.

4.Download PHUZZ into Ubuntu and open it in VS Code.

  In the Ubuntu terminal, run:
    mkdir -p ~/projects
    cd ~/projects
    git clone https://github.com/gehaxelt/phuzz.git
    cd phuzz
    git rev-parse HEAD
    code .

  Your files now live at: \\wsl.localhost\Ubuntu\home\YOUR_LINUX_USERNAME\phuzz

5.Check the experiment configuration before starting it.

  Run these commands in the VS Code Ubuntu terminal:
    cd ~/projects/phuzz/code
    docker compose config --services
  The service list should include the published quick-run services:
    db
    web
    fuzzer-dvwa-sqli-low-1
  Other services may also appear.

6.Build and start the database.
  From ~/projects/phuzz/code, run:
    docker compose up -d --build --force-recreate db
  Then inspect its startup:
    docker compose logs -f db
  Wait until database initialization finishes and it reports that it is ready for connections. The repository suggests an initial wait of approximately 15 seconds.
  Press Ctrl+C to stop following the logs. This does not stop the database.

7.Build and start the PHP web application.
  Run:
    docker compose up -d --build --force-recreate web
    docker compose logs -f web
  Wait for startup to finish and check for setup or database connection errors. Press Ctrl+C to leave the log viewer.

  Check the running services:
    docker compose ps
  If you want to inspect the application in your Windows browser, read the PORTS column. For example, a mapping ending in 8080->80/tcp means you can try:
  http://localhost:8080/

  The command runs in the foreground, displaying output in your terminal. Allow it to finish initializing, then let it fuzz for a recorded period—for example, five minutes for an initial demonstration. That duration is a suggested setup check, not the paper’s experimental duration.

  During execution, PHUZZ generates test requests, the web application processes them, and feedback helps guide subsequent tests. Results are saved for inspection.

  Press Ctrl+C once to stop the foreground run and allow shutdown to complete. Unlike exiting logs -f, interrupting compose up stops its attached containers.

8.Open and understand the results.
  The published example identifies this results file:
    fuzzer/output/fuzzer-1/vulnerable-candidates.json
  Open it in VS Code:
    code fuzzer/output/fuzzer-1/vulnerable-candidates.json

9.Preserve evidence before starting another experiment.

  After stopping the fuzzer, run:

  PHUZZ_RUN_DIR="$HOME/projects/phuzz-evidence/run-01"
  mkdir -p "$PHUZZ_RUN_DIR"

  git rev-parse HEAD > "$PHUZZ_RUN_DIR/commit.txt"
  docker version > "$PHUZZ_RUN_DIR/docker-version.txt"
  docker compose version > "$PHUZZ_RUN_DIR/compose-version.txt"
  docker compose config > "$PHUZZ_RUN_DIR/compose-resolved.yml"

  docker compose logs --no-color --timestamps \
    fuzzer-dvwa-sqli-low-1 > "$PHUZZ_RUN_DIR/fuzzer.log"

  cp -r fuzzer/output/fuzzer-1 "$PHUZZ_RUN_DIR/"

10.Shut down the lab after saving results.
  Run:
    docker compose down
  This stops and removes all containers, networks, and volumes created by the compose file.

Switch the web application to XVWA

1.Create an XVWA override file.
  cat > compose.xvwa.yml <<'YAML'
  services:
    web:
      environment:
        APPLICATION_TYPE: xvwa
  YAML

2.Start the database, then XVWA
  docker compose -f docker-compose.yml -f compose.xvwa.yml \
  up -d --build db

  Check the database readiness:
    docker compose -f docker-compose.yml -f compose.xvwa.yml \
    logs -f db

    Once initialization finishes, press Ctrl+C to leave the log viewer.

  Start the web application:
    docker compose -f docker-compose.yml -f compose.xvwa.yml \
    up -d --build --force-recreate web
  
  Follow its startup logs:
    docker compose -f docker-compose.yml -f compose.xvwa.yml \
    logs -f web
  Wait for application initialization and Apache startup to finish. Press Ctrl+C.
  Based on the supplied XVWA configuration, try http://localhost:8080/xvwa/

3.Run one fuzzer against XVWA's SQL injection endpoint.
  docker compose -f docker-compose.yml -f compose.xvwa.yml \
  run --rm --build --no-deps \
  --name phuzz-xvwa-sqli-item \
  -e FUZZER_CONFIG=xvwa/sqli_item \
  -e FUZZER_NODE_ID=101 \
  fuzzer-dvwa-sqli-low-1

4.After the XVWA fuzzer has exited, stop its web container:
  docker compose -f docker-compose.yml -f compose.xvwa.yml \
  stop web
